This is what the expectation is for this entire module

Event Operations
Need to be able to see a list of all the events happening for a day, week, month or custom period. This could be public events (which people book into: eg. kayaking) or it could be a private booking (casual booking with a single activity or multiple activities spanning 1 or many days, or a regular or seasonal booking with facilities booked for multiple days for one or more activities). A private booking will be a single booking whereas a public session may consist of multiple bookings for that slot. 

Now let me explain the setup of the public sessions.
We create an event, and then add all possible facilities and resources that will be utilized in the event. Then we add the timeslots (dates and times) and mention which facility and resource will be used for that timeslot. In most cases, we already know what facilities and resources are going to be utilized. In some cases, the rostering may not have happened yet, so the resources may not be known immediately, but the event will still need to be sold for those dates. SO for these scenarios, the timeslot may be active, but not rostered yet.

Now, once the event is created with the facilities, resources and the dates, then the packages are created. The packages will be created with the dates of the event (every package doesn't necessarily have to be for all dates and times), and the corresponding items to book out the allocation from the facility and resource slots. Now, the resource item may be linked to multiple resources, but for a given day and time, the availability will be based only off the number of resources the timeslot has been created for in the events. For these not rostered slots, the availability will ignore that not rostered resource(s) and consider the rest of the facilities and resources capacity when taking in bookings. 

Next, let's consider the types of bookings that can be placed:
Public bookings - these are bookings where people have purchased packages to a particular event session
Private bookings - these are custom bookings made by a customer for a time. These could be casual on-off bookings, casual recurring bookings, or seasonal/regular bookings (bookings with multiple dates for a given period, for one or many packages/activities)

Coming back to the event operations screen. This is to be used to make sure that all the events (be it public or private) are good to go. Now for clients where rostering is not applicable, this will largely be ok the 1st time you have a look cos everything will be allocated properly and there won't be a shortage cos the system would have booked everyone in based on availability. In the case of clients who have rostering, we may see some public sessions that have more bookings than the actual availability (eg. the public session was made up of a facility that can accommodate 10 people and 2 boats that can accommodate 4 people each. Based on that the availability would have been 8 cos considering the facility and the boat, the least capacity would have been the availability. Let's assume this was before the rostering of the instructor took place and bookings with 8 attendees were made. Once the rostering was done, there were only 2 instructors allocated, and each instructor can take on 3 people. By that logic, there are still 2 attendees who need to be catered to, so we need to pay attention to them). These sessions will say that they need attention. These sessions could also show that attention is required, in case a facility or resource becomes unavailable suddenly, and those bookings get de-allocated. 

Now, let's look at the operations that can be performed
1. For a given session, should be able to temporarily increase (or decrease) the capacity of any given facility or resource assigned to that timeslot. This way, we can temporarily increase capacity to accommodate those additional bookings. Ideally should be able to allow this capacity for the remaining sessions of the day as well.
2. We should be able to assign a new resource to take on those additional bookings. Here, we need to show the best candidates to be assigned. When it comes to human resources, in some cases, they will have a skill assigned to them. So those people who have the skill that matches the event will have to be shown as most suitable. If there is no such skill assigned, then resources belonging to that venue that belong to the same resource category should be shown. Next will be those who belong to the same resource category but not to the venue. If there is an eligible resource who is at a different venue, but whose allocations can be moved to someone else without an issue, then that person should also show but with a review option so that we know what exactly is happening. Optionally, there should be a search section where you can search for a specific resource and assign them. If the resource is not available, then it should show that. A view schedule option should also be visible to get a rough understanding of that resources allocations. Now, the same should be applicable to non-human resources as well. If a facility is under capacity, then the only option should be to increase the capacity
3. We should be able to move some of the bookings to a different session. So, instead of assigning a resource or adjusting the capacity, we should be able to move some of those bookings to a new session. Now here, we may move to a session of the same activity or should be able to move to a different activity as well. This is because, sometimes the customers may not be available for any other activities so they may need to somehow utilize whatever is available. Now here, there could be activities where the price differs. In those cases, the user should be able to decide whether to keep the same price or use the updated price. If they use the same price (need a user right for this), then the booking can just be rescheduled, if not, the operation needs to continue in the booking manager (optima's booking screen). In some cases, the booking data may differ due to a different package being selected (eg. questionnaire, attendee details, waiver form). In those cases, the user has to go to the booking manager to make the change
4. Should be able to create an additional session by copying this session, and then moving those customers to that newly created session. You should be able to create multiple sessions ideally. If for any of those sessions that we want to create, there is one or many resources conflicting, then you should be able to select a replacement, or exclude them for the session. Should have an advanced pattern selection feature where we can select multiple dates and timeslots and create the timeslots across those. 
5. Should be able to move an entire session to a new timeslot which will automatically move all the bookings as well. If a specific resource is not available for the new timeslot, should be able to select an alternate/replacement resource. Would be nice to have a calendar visual here to drag and drop the session, with the date and time selection also there
6. Should be able to view a list of bookings for a session
7. Should be able to move to the notify attendees screen for a selected session

Additionally, should be able to select multiple sessions assign resources one by one for each session, like a workflow. This is to make things easy so they don't have to select a session, go and assign, and then come back and select the next session and go and apply

For private bookings:
1. You should be able to reschedule the booking. Now here, you may get a booking where all the timeslots are the same (eg. galaxea centre, Eric and snorkeling set ae all from 10-12) or you can get where there are different timeslots (some from 10-12 and the rest from 12-2). If those are part of different packages within the same booking, then they should show as different timeslots but if not, they should show combined using the package name. If only 1 package, then the booking name should suffice, but if not, booking name plus the package name should show. When moving these around, you should be able to move everything together or individually. Now, in the case of recurring or seasonal bookings where more than 1 day is possible, these should be broken down by day. When moving a session, should be able to move only that or move all the other days with it. Remember, these are the advanced options, so the simple moves should be easy to handle. calendar move would be great.
2. Should be able to replace any of the facilities or resources in the booking


Let's move on to the resource operations

Now here, we would like to see a list of all the resources and see a summary of their work, etc. The main functions of this screen should be

1. Making the resource unavailable for today, a period or forever (if a human resource resigns or if a resource is broken and no longer usable). when this happens, should be able to remove that resources slots for the period, block the resource from taking on any other bookings and make the resource inactive (only if it's forever). Optionally, they can not remove the slots or block the resource, in case they want to just take on new bookings. Now the system should automatically allocate the ones it can, either fully or partially, and then show the ones that cannot be automatically done (those will just get de-allocated). For private bookings, it should ask for a replacement and if that resource is there multiple times in the booking (seasonal, regular, recurring), then should ask whether to replace for all other dates as well. If can't then should not allow. With that it should just show a summary of what happened, and then have a link to open the event operations page so that the user can then decide whether they want to assign another resource or move the booking, or increase capacity, etc. 

Ideally this closure should be recorded somewhere with the status of which bookings needed action so that the user an always check and make sure that the imact of the operation is tackled

2. Should be able to re-assign their work. This will work somewhat like the assigning resource tool where it will show replacement suggestions with the additional options to search for resources

3. Move to another venue. This should only be applicable to movable resources. Here again, it's similar to the make unavailable section, except that there won't be marking unavailable and for the new venue, need to be able to select which new timeslots to allocate the resources to. Allocation of the resources for the previous venue should happen similar to the make unavailable section, and the rest should be handled in the event operations screen


Let's look at the facility operations now

This is going to be slightly different to the resource operations. View-wise, it should show similarly. Feature-wise:
1. I should be able to drag and drop bookings from one slot to another. During this, we need to take into consideration those different casual and regular booking scenarios mentioned above (moving together, moving individually). We should be able to drag and drop from one day to another as well. I should be able to move a public session from one facility to another as well. This will need to make sure that the timeslots get created for that facility and a new package is created with this new facility, but maintaining the same price. May need a technical discussion here
2. Close a space - close one or many spaces for a day or period. Should be able to close it or just move the bookings out of it for the period. Then should be able to move those bookings to different slots. In cases like regular bookings, that slot may just be unutilsed so in those cases, we simply deallocate only. When doing so, we need to make sure that other facilities and resources for that same slot or day are being utilised or not (option to select). If there is a price change then should give the option to keep the price as it is, if there is a need to change, then allow the change, but flag that booking for booking manager updates required. Same case if there are questionnaire, waiver changes. There won't be any ask hirer to confirm feature as such. The booking is moved, and then we either inform the client or else keep it as it is. No need to handle those from a system perspective. For quite a few seasonal bookings, the price may not change cos it's a seasonal price. For regular bookings, it may change if it is removed from the booking or moved to a different location, but if they are invoiced monthly, it will just reflect in the next months invoice. Here too, will be good to track closures and the booking actions required
